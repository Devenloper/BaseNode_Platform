# System Mode

Документ описывает глобальные режимы работы системы,
их назначение и архитектурные ограничения.

Документ является нормативным.
Нарушение правил считается критической архитектурной ошибкой.

---

# 1. Назначение

System Mode — это глобальное состояние системы,
которое ограничивает допустимость выполнения команд.

System Mode:

- не является доменной сущностью;
- не является событием;
- не хранится в Event Store;
- не влияет на Domain Layer напрямую;
- применяется исключительно в Application Layer.

Цель:

- защита целостности данных;
- операционная безопасность;
- аварийный контроль;
- юридическая фиксация состояния.

---

# 2. Утверждённые режимы

В системе определены:

- NORMAL
- READ_ONLY
- (опционально) MAINTENANCE

---

# 3. NORMAL

Стандартный режим работы.

- все write-команды разрешены;
- FULL_MODE применяется;
- RBAC применяется;
- конфликтная модель работает штатно.

---

# 4. READ_ONLY

Режим защиты системы от изменений.

Используется при:

- расследованиях;
- рассинхронизации интеграций;
- инцидентах;
- юридической фиксации состояния.

В READ_ONLY:

- запрещены все write-команды;
- запрещены override;
- запрещены compensating события;
- запрещена запись новых событий;
- разрешены read-запросы;
- разрешён audit.

READ_ONLY имеет приоритет над FULL_MODE.

---

# 5. MAINTENANCE (опционально)

Технический режим.

- пользовательские команды запрещены;
- допускаются системные операции;
- используется для миграций и обслуживания.

Добавляется без нарушения архитектуры.

---

# 6. Граница ответственности

## 6.1 Application Layer

Application Layer:

- проверяет System Mode до выполнения команды;
- блокирует write-команды при READ_ONLY;
- формирует системную ошибку;
- логирует попытки нарушения режима.

Application — единственная точка,
где проверяется режим.

---

## 6.2 Domain Layer

Domain:

- не знает о System Mode;
- не содержит условий, зависящих от режима;
- не меняет поведение в зависимости от режима.

---

## 6.3 Infrastructure Layer

Infrastructure:

- хранит текущее значение режима;
- предоставляет интерфейс получения режима;
- не принимает решений;
- не блокирует операции самостоятельно.

---

# 7. Celery и фоновые задачи

Celery-задачи:

- не имеют права писать события напрямую;
- обязаны использовать Application Layer;
- обязаны проходить проверку System Mode.

Если режим сменился на READ_ONLY,
все новые write-операции должны быть отклонены.

Фоновая задача не является исключением.

---

# 8. System Mode и Event Sourcing

System Mode:

- не создаёт событий при смене;
- не изменяет историю;
- не влияет на replay;
- не нарушает append-only модель.

Если команда заблокирована режимом —
событие не создаётся.

---

# 9. System Mode и FULL_MODE

System Mode и FULL_MODE — разные механизмы.

System Mode:
- системный контроль.

FULL_MODE:
- бизнес-политика оплаты.

Правила:

- READ_ONLY имеет приоритет;
- FULL_MODE применяется только в NORMAL;
- Domain не знает ни о FULL_MODE, ни о System Mode.

---

# 10. System Mode и OFFLINE

OFFLINE:

- не изменяет System Mode;
- не обходит READ_ONLY;
- не разрешает write-команды при READ_ONLY.

OFFLINE не является альтернативой System Mode.

---

# 11. Управление режимом

System Mode может быть изменён только пользователем с ролью ROOT.

Смена режима:

- логируется;
- фиксируется в audit;
- не является доменным событием;
- не записывается в Event Store.

---

# 12. Запрещено

Запрещено:

- проверять режим в Domain Layer;
- менять режим из UI напрямую;
- использовать режим как бизнес-логику;
- создавать события для смены режима;
- обходить режим через Celery;
- писать события напрямую в Event Store.

---

# 13. Критерий корректности

System Mode реализован корректно, если:

- ни одна write-команда не проходит при READ_ONLY;
- Celery не может обойти режим;
- replay не зависит от режима;
- Domain полностью изолирован от режима.

---

# 14. Заключение

System Mode — это механизм защиты архитектуры,
а не инструмент повседневной работы.

Он должен:

- быть простым;
- быть предсказуемым;
- использоваться редко;
- работать одинаково в любых условиях.

Нарушение правил System Mode
считается критической архитектурной ошибкой.
