# Чек-лист ИИ-разработки
## BaseNode Platform

Версия: 1.0  
Статус: Обязателен для PR / Ревью  
Применяется к: Любой разработке с использованием ИИ  

Этот чек-лист должен быть пройден перед:
- Открытием Pull Request
- Слиянием кода
- Принятием проектного решения, предложенного ИИ

Если хотя бы один критичный пункт не выполнен — изменения пересматриваются.

---

# 1. Архитектурное соответствие

[ ] Нет прямых UPDATE доменных данных  
[ ] Нет DELETE доменных данных  
[ ] Нет изменения уже сохранённых событий  
[ ] Нет бизнес-логики в read-model  
[ ] Нет прямого доступа к БД другого домена  
[ ] Нет распределённых транзакций между доменами  
[ ] Нет скрытых override  

---

# 2. Дисциплина агрегата

Для каждого нового или изменённого агрегата:

[ ] Чётко определено состояние агрегата  
[ ] Определены команды  
[ ] Определены доменные события  
[ ] Перечислены инварианты  
[ ] Используется поле version  
[ ] Проверяется ожидаемая версия  
[ ] Обрабатывается конфликт версий  

---

# 3. Целостность Event Sourcing

[ ] Все изменения состояния происходят через события  
[ ] Нет скрытой мутации состояния  
[ ] События содержат обязательные поля:
    - event_id
    - aggregate_id
    - aggregate_type
    - timestamp (UTC)
    - actor
    - causation_id
    - correlation_id (если применимо)

[ ] Snapshot не является источником истины  
[ ] Повторное воспроизведение событий даёт идентичное состояние  

---

# 4. Идемпотентность

Для интеграций / API / OFFLINE-синхронизации:

[ ] Используется external_event_id  
[ ] Обработаны дубликаты  
[ ] Повторная обработка не меняет состояние  
[ ] OFFLINE-sync не создаёт дубли  

---

# 5. Принцип компенсации

Если реализована корректировка:

[ ] Используется компенсирующее событие  
[ ] Есть ссылка на исходное событие (compensation_for_event_id)  
[ ] Нет переписывания истории  
[ ] Нет удаления событий  

---

# 6. Интеграция с PMS (если применимо)

[ ] PMS остаётся источником истины  
[ ] Проверяется версия / timestamp  
[ ] Устаревшие данные игнорируются  
[ ] Обрабатывается PMSOutdatedEventIgnored  
[ ] Нет замены источника истины локально  
[ ] Режим PMS_UNAVAILABLE соблюдается  

---

# 7. OFFLINE-поведение

[ ] OFFLINE-события сохраняются  
[ ] Используется детерминированный event_id  
[ ] Сохраняется порядок синхронизации  
[ ] Нет silent rollback  
[ ] При расхождении создаётся Conflict  

---

# 8. Конфликтная модель

Если возможен конфликт:

[ ] Определено событие конфликта  
[ ] Конфликт не решается автоматически  
[ ] Есть событие разрешения  
[ ] Конфликт отображается в read-model  

---

# 9. Финансовая целостность (если применимо)

[ ] Сумма не изменяется после фиксации  
[ ] Возврат — отдельное компенсирующее событие  
[ ] Проживание и услуги не объединены в одну транзакцию  
[ ] Соблюдена защита закрытого периода  
[ ] Валюта и курс зафиксированы в момент операции  

---

# 10. Лояльность (если применимо)

[ ] Баланс не может стать отрицательным  
[ ] Проверяется версия агрегата  
[ ] Обрабатывается конфликт конкурентного доступа  
[ ] Баллы не трактуются как деньги  
[ ] Нет ретроспективного пересчёта  

---

# 11. HR и закрытые периоды (если применимо)

[ ] Закрытый период защищён  
[ ] Нет событий задним числом  
[ ] Корректировка только через новый период  
[ ] WorkEvent в закрытом периоде не изменяется  

---

# 12. Безопасность и аудит

[ ] Логируется доступ к ПДн  
[ ] Нет массовой выгрузки без события  
[ ] Проверяются права ролей  
[ ] ENGINEER не имеет доступа к ПДн  
[ ] Записи аудита неизменяемы  

---

# 13. Дисциплина read-model

[ ] Нет бизнес-валидации в проекции  
[ ] Проверена возможность пересборки  
[ ] Обрабатывается превышение допустимой задержки  
[ ] Нет write-логики в проекции  

---

# 14. Тестирование (обязательно)

Для каждой новой функции:

[ ] Happy path  
[ ] Конфликт версий  
[ ] OFFLINE-сценарий  
[ ] Ошибка интеграции  
[ ] Дубликат события  
[ ] Попытка изменения закрытого периода  

Если тестов нет — PR не принимается.

---

# 15. Специфика ИИ-разработки

[ ] Решение проверено на соответствие Архитектурному манифесту  
[ ] Нет “временных упрощений”  
[ ] Нет обходных флагов  
[ ] Нет “админской кнопки исправить”  
[ ] Не изменён архитектурный фундамент  

Если ИИ предложил изменение архитектуры:

[ ] Это явно задокументировано  
[ ] Рассмотрено отдельно  
[ ] Утверждено до реализации  

---

# 16. Подтверждение ревьюера

Ревьюер подтверждает:

[ ] Все пункты проверены  
[ ] Архитектурная целостность сохранена  
[ ] История событий остаётся источником истины  
[ ] Двойной источник истины не создан

# Правило слияния

Если любой критичный пункт не выполнен:
→ Изменения не сливаются.

Стабильность архитектуры важнее скорости внедрения.
