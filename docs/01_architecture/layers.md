# Layers

Данный документ фиксирует **утверждённую слоистую архитектуру системы**  
и правила взаимодействия между слоями.

Документ является нормативным и дополняет
`architecture_constitution.md`.

---

## 1. Общий принцип

Система построена по принципу **строгой слоистой архитектуры**.

Слои:

1. Domain
2. Application
3. Infrastructure
4. Interface

Каждый слой имеет чёткую ответственность и ограничения.  
Нарушение границ слоёв запрещено.

---

## 2. Domain Layer

### Ответственность
- бизнес-модель;
- агрегаты;
- доменные события;
- инварианты;
- value objects.

### Характеристики
- детерминированный;
- не содержит побочных эффектов;
- не зависит от инфраструктуры.

### Запреты
Domain Layer:
- не знает о БД;
- не знает о HTTP / API;
- не знает о UI;
- не знает об интеграциях;
- не знает о ролях и доступах;
- не знает о SystemMode и FULL_MODE;
- не содержит SQL;
- не использует async/await для I/O.

---

## 3. Application Layer

### Ответственность
- обработка команд;
- orchestration use-cases;
- применение системных и бизнес-политик;
- проверка ролей и режимов;
- контроль конфликтов;
- публикация доменных событий;
- OFFLINE-оркестрация.

### Характеристики
- координирующий слой;
- не содержит бизнес-модели;
- не хранит состояние.

### Внутренняя дисциплина
Application Layer **обязан** быть декомпозирован:

- Command Handlers
- Policies
- Guards
- Services
- Dispatcher

### Запреты
Application Layer:
- не содержит SQL;
- не реализует доменные инварианты;
- не изменяет состояние напрямую;
- не вызывает агрегаты других контекстов напрямую.

---

## 4. Infrastructure Layer

### Ответственность
- Event Store;
- базы данных;
- проекции;
- очереди;
- интеграции;
- внешние адаптеры;
- сериализация.

### Характеристики
- содержит технические детали;
- может быть заменяемым;
- не содержит бизнес-решений.

### Запреты
Infrastructure Layer:
- не принимает бизнес-решений;
- не проверяет инварианты;
- не содержит правил доступа;
- не содержит FULL_MODE или RBAC логики.

---

## 5. Interface Layer

### Ответственность
- HTTP API;
- CLI;
- UI.

### Характеристики
- адаптационный слой;
- не содержит логики.

### Запреты
Interface Layer:
- не содержит бизнес-логики;
- не принимает решений;
- не проверяет инварианты;
- не заменяет Application Layer.

---

## 6. Правило взаимодействия слоёв

Допустимые зависимости:

Interface → Application → Domain  
Infrastructure → Application / Domain (через интерфейсы)

Запрещено:
- Domain → Application
- Domain → Infrastructure
- Application → Interface
- Domain → Interface

---

## 7. Контроль соблюдения

Нарушение границ слоёв считается **архитектурной ошибкой**  
и подлежит исправлению независимо от стадии разработки.
